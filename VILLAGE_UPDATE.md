# Village update · 0.5

Production release uses the existing GitHub `main` → Vercel `world-pwa` connection. Publishing does not replace browser saves.

## Town presentation

Completed infrastructure brings surrounding development: the hall has a cottage and well; the sawmill gains a carpenter's shop and forester's home; the garden gains a produce stall and cottage; the blacksmith gains a tool stall and cottage; the kitchen gains a bakery and outdoor table. The hall upgrade adds another cottage. Existing completed buildings receive the same details immediately. Details are decorative and have no upkeep, production, or resource costs.

Primary building sprites occupy 19% of the desktop map width and 20% on phones, down from 25% and 29%. Surrounding structures use 8–12%. Footprints, paths and destinations are explicit data, not random layout or save-dependent RNG.

An original painted character sheet supplies four walking/chopping/mining/hammering poses per row. Residents travel between built locations, stop and return; background and earned working crews remain separately labelled. Smoke and river highlights add light ambient movement. Reduced-motion preferences stop all animation. Art is bundled and precached locally.

Greenhaven uses dark timber, parchment and forest green. A palette change is available when viewing the already-discovered river location; no territory chooser or place name is shown before its discovery. That location remains a charted frontier, **not a playable second settlement**. Inter-region logistics and a broader campaign remain future work.

## Activities and progression

The saved activity ID `gym` remains stable and is displayed as **Lift weights**. Existing history, credentials and ore jobs are retained. Lifting still funds ore gathering, but never gates construction. The default blacksmith now requires one qualifying cardio accomplishment. The former extra strength requirement for the hall is removed; its hiking, soccer, nutrition, material and completed-building requirements remain.

`strengthMode` and `strengthCount` remain accepted in legacy rule data for import compatibility. The old strength-selection UI and hardcoded hall gate have been removed. They no longer affect progression. A developer-supplied `gym` gate is ignored by requirement evaluation, so lifting cannot silently become mandatory.

## Guide and requests

The Guide has resource sources, activities, visible buildings and instructions. Quantities, thresholds, daily caps, production rates and timings come from the active saved rules. Resource entries link to logging, workshops or requests. The hidden hall upgrade is listed only under the same visibility conditions as construction. Unencountered exploration currency and place names stay hidden.

General queue, offline, correction and installation instructions live in the Guide. Normal play retains costs, shortages, timers and outcomes. Motivational filler and the passive Mara quotation have been removed.

Each request shows its supplies, exact immediate rewards and practical purpose. Requests remain optional, one-time exchanges. The bench and supper add visible furnishings, including for previously completed requests. Gold still has only the existing merchant exchange; the Guide explains that gold sources are finite.

## Existing saves

The structural save schema stays at 3; `contentVersion: 2` marks this prospective content update. `migrate` validates and clones the original world, retains all logs, inventory, ledger entries, credentials, buildings, discoveries, fulfilled requests and queued work, then adjusts future lifting gates. A migration audit entry and rule-history snapshot document the change. An unbuilt building whose old requirements were already earned receives a permanent building credential, so this change does not relock it or invent cardio history. Repeat loads do not reapply the update. Customized activity rewards, caps, offline allowance and existing job snapshots are retained.

When loading an older browser save, `store.load` archives its untouched original text once at `<world-key>.pre-village2`. Settings → Export pre-update backup downloads that original snapshot. Older `.pre-v3` archives remain available as a fallback. A downloaded world export remains the independent backup; browser backups share the same storage.

`e2e/fixtures/v04-world.json` is an anonymous test export generated by the previous committed engine. It contains earned history, custom rules, completed buildings and a request, active gathering, crafting and construction. Both unit and browser import tests verify preservation. It contains no user records.

## Review boundaries

Browser verification uses Chromium at phone and desktop dimensions. Actual iPhone Safari/Home Screen behavior still needs device review. This revision does not enable accounts or create hosting resources. Production uses the existing static Vercel site.
